# Westcon Meeting Intelligence · arquitectura v1.0

## Principio

La UI recoge el mínimo posible. La complejidad vive en el motor de conocimiento, research, evidencia, priorización narrativa y composición PowerPoint.

## Flujo

1. **Input mínimo** — partner, rol, objetivo y, cuando corresponde, fabricante foco.
2. **Contexto privado opcional** — negocio/pipeline/certificaciones/arquitectura.
3. **Runtime research** — partner + vendors seleccionados + objetivo/caso de uso.
4. **Knowledge fusion** — corpus FY27 + vendor intelligence + verticales + evidencia pública.
5. **Narrative planning** — el perfil cambia el orden y profundidad, no el destinatario: la salida siempre es partner-facing.
6. **Composition** — slides FY27 existentes + slides nuevas con la misma identidad visual.
7. **Outputs** — PPTX, briefing interno, notas y PDF vía impresión.

## Capas de conocimiento

- Corporate FY27.
- 12 datasheets verticales.
- 36 fichas de fabricante.
- Servicios Westcon y BLUEPRINT.
- Competitive context interno.
- Analyst/public evidence.
- News/media/cases/channel/technical evidence.
- Partner runtime intelligence.

## Política de evidencia

Cada evidencia pública conserva URL, publisher, fecha, tipo y score de autoridad. La generación visible evita inferencias no demostradas, especialmente posiciones de analistas.

## Seguridad de datos

Los datos privados de reunión viven en el navegador. GitHub Actions solo procesa información pública de fabricantes.
